Flint

A systems language that compiles straight to a native ELF executable — with classes, generics, collections, and direct syscall access, and no runtime to install.

Hello, Flint

Everything is a .flint file. The compiler flintc produces a standalone binary in one step (it assembles and links for you).

hello.flint
int main() {
    print("hello, flint");
    print("\n");
    return 0;
}
build & run
$ flintc hello.flint -o hello
$ ./hello
outputhello, flint

What you can do

Classes & OOP

Fields, constructors, methods, inheritance, abstract classes, interfaces, properties, statics, and enums.

Generics

Generic classes with type inference and explicit instantiation (Vessel<Pair<int,int>>).

Collections

Generic list, queue, hashset, hashmap, and dictionary with int, string, and object elements.

Raw memory

Escape analysis, alloc/free, raw pointers, sized load/store, and direct syscalls.

Concurrency

Threads, mutexes, atomic CAS, and network I/O for building servers.

Fixed-point math

A Q48.16 fixed-point numeric model with math.* builtins — no floating point, no surprises.

Getting started

Building a Flint program, the flintc command-line interface, and the flint.toml manifest.

Clone & build

The whole project — the flintc compiler, the standard library, and the examples — lives in one repository on GitHub. Clone it, build the compiler with cargo, then compile your first program:

get the toolchain
$ git clone https://github.com/Quackster/flint.git
$ cd flint
$ cargo build --release
$ target/release/flintc examples/hello.flint -o hello
$ ./hello

Requires cargo (the Rust toolchain) to build the compiler and as / ld (binutils) on the PATH to link programs. The resulting binary is target/release/flintc (debug builds go to target/debug/flintc).

What you need

Flint compiles to a standalone native ELF executable. The toolchain is a single Rust binary, flintc, which drives the system assembler (as) and linker (ld) for you. There is no runtime to install on the target — the runtime is linked into every binary.

Build a single file

Pass one or more .flint files and an output path. Multiple files are concatenated (each keeps its own package header).

build & run
$ flintc hello.flint -o hello
$ ./hello
options-o <FILE> write output to FILE (default: <first input> minus .flint) -S stop after generating assembly (print to stdout) --manifest F read source files from a TOML manifest --dir D compile every .flint file in D (sorted) -h, --help print this help

Assembly only

-S stops after code generation and prints the assembly to stdout — useful for inspecting the generated .s.

inspect the assembly
$ flintc hello.flint -S > hello.s

Multi-file projects

Three equivalent ways to build a multi-file program:

  • Positional: flintc util.flint main.flint -o app
  • Manifest: flintc --manifest flint.toml -o app
  • Directory: flintc --dir myproject -o app

A flint.toml manifest is a single sources array of paths relative to the manifest file:

flint.toml
sources = ["util.flint", "main.flint"]

See Modules & multi-file for the full picture, including a worked example.

The toolchain

How flintc turns a .flint file into a standalone native ELF executable.

The pipeline

flintc is a zero-dependency Rust compiler. Source flows through four stages, then the system assembler and linker finish the job:

pipelinelexer → parser → monomorphize → codegen → .s → as → ld -e _start → ELF
  • lexer — tokens (keywords, literals, operators, labels).
  • parser — an AST of types, classes, and statements.
  • monomorphize — instantiates generic classes for each concrete type argument (this is how list<int> and list<string> become distinct code).
  • codegen — emits x86-64 assembly plus the runtime.

Assemble & link

Codegen writes a .s file that is concatenated with two assembled runtime objects and linked into a freestanding binary. The entry point is forced to _start (there is no C runtime):

under the hood
user.s      (your program + generated code)
intrinsic.s (the Flint runtime: memory, syscalls, objects)
collection.s (the collection runtime: list, queue, hashset, hashmap)
        │
        ├── as user.s      -o user.o
        ├── as intrinsic.s -o intrinsic.o
        ├── as collection.s -o collection.o
        └── ld -e _start user.o intrinsic.o collection.o -o out

The runtime

Two flat-assembly files are linked into every binary:

  • intrinsic.s — alloc/free, retain/release, memcpy, the syscall bridge, per-class object destructors, and thread/mutex primitives.
  • collection.s — the runtime for the generic collections (list, queue, hashset, hashmap) including their element-release hooks.

Because the runtime is static and small, a "hello world" binary is fully self-contained: no shared libraries, no interpreter, no install step.

Rebuilding. The compiler is built with cargo build --release; the resulting binary is target/release/flintc. The repository ships a test suite — bash tests/run_tests.sh (79 feature tests) and cargo test (8 unit tests) — that exercises every language feature end to end.

Modules & multi-file

Packages, import, and building a program from several .flint files.

Packages & imports

A file declares its package on its first line. The entry-point file (the one with main) has no package header. A file in another package is pulled in with import of the fully-qualified class:

util.flint
package demo.stats;

class Stats {
    static int sum(list<int> xs) {
        int s = 0;
        int i = 0;
        while (i < len(xs)) {
            s = s + xs.get(i);
            i = i + 1;
        }
        return s;
    }
}
main.flint
import demo.stats.Stats;

int main() {
    list<int> xs = new list<int>();
    xs.add(4);
    xs.add(9);
    printi(Stats.sum(xs));
    print("\n");
    return 0;
}

The standard library follows the same rule — its classes live in package std, so you import std.Math and so on (see the Standard library pages). When you compile a program that uses the standard library, pass the library sources along with your file: flintc src/stdlib/*.flint myprogram.flint -o out.

Building three ways

all three produce the same binary
# positional
$ flintc util.flint main.flint -o app

# manifest
$ flintc --manifest flint.toml -o app

# directory (compiles every .flint in the dir, sorted)
$ flintc --dir myproject -o app

Worked example

The examples/multifile project — a Stats class in package demo.stats plus an entry point that imports it:

examples/multifile/main.flint
import demo.stats.Stats;

int main() {
    list<int> xs = new list<int>();
    xs.add(4);
    xs.add(9);
    xs.add(1);
    xs.add(7);
    printi(Stats.sum(xs)); print(" ");   // 21
    printi(Stats.max(xs)); print(" ");   // 9
    printi(Stats.mean(xs)); print("\n"); // 5
    return 0;
}
output (dir, manifest — identical)21 9 5

Types & literals

A small, flat type system: one 64-bit integer type for all integer kinds, a byte boolean, strings, and class types.

Integer types

byte, short, int, long, and char are all 64-bit integers in v1 — they are synonyms that document intent. There is a single numeric model, so arithmetic never changes width. Booleans are a one-byte boolean holding 0 or 1.

Literals

  • Decimal: 42, -7.
  • Hex: 0x1F, 0xFFFFFFFF. There are no 0b binary or 0o octal literals — write those values in decimal or hex.
  • String: "hello" (double-quoted, backslash escapes).
  • Boolean: true, false.
  • Null: null (string and object null).

There are no floating-point literals. Real-valued math uses the Q48.16 fixed-point model — see Fixed-point numbers.

Hex literals wrap at the 64-bit boundary

Hex literals are parsed as unsigned 64-bit values stored in a two's-complement slot. Values up to 0x7FFFFFFFFFFFFFFF stay positive; values from 0x8000000000000000 up wrap negative.

examples/hexwrap.flint
int main() {
    int a = 0xFFFFFFFFFFFFFFFF;
    printi(a);                        // -1 (all 64 bits set)
    print("\n");
    int b = 0x7FFFFFFFFFFFFFFF;
    printi(b > 0 ? 1 : 0);          // 1 (i64 max stays positive)
    print("\n");
    int c = 0x8000000000000000;
    printi(c < 0 ? 1 : 0);         // 1 (i64 min, wraps negative)
    print("\n");
    int d = 0xFFFFFFFF;
    printi(d);                      // 4294967295 (fits positive; no wrap)
    print("\n");
    int e = 0x10;
    printi(e);                     // 16
    print("\n");
    printi(a + 1);                 // 0 (two's complement wrap)
    print("\n");
    return 0;
}
output-1 1 1 4294967295 16 0
Note. 0xFFFFFFFF is not -1 — it is 4294967295, because it fits in the positive range. Only values with the top bit set (0x8000000000000000 and up) wrap negative. 0xFFFFFFFFFFFFFFFF (all 64 bits) is -1.

String literals

Strings are NUL-terminated byte buffers. They support backslash escapes (\n, \t, \", \\, …). See Strings for the full model, including that a string + int is pointer arithmetic and two strings + concatenate.

Variables & scope

Flat function-level scope: there is no block-level shadowing — re-declaring a name re-declares the same variable.

Declaration

Variables are declared with a type, then optionally initialized. Re-assignment is plain =. There are no let/var keywords.

declaration
int x = 10;        // declare + init
string name = "flint";
x = x + 5;        // re-assign

Flat scope — no block shadowing

This is the single most important (and most surprising) scoping rule: a Type name declaration inside an inner block does not create a new variable. It re-declares the same variable, overwriting it — and the new value persists after the block ends.

examples/scope.flint
int main() {
    int v = 10;
    if (1) {
        int v = 20;          // re-declares v
        printi(v);         // 20
    }
    printi(v);             // 20 (the re-declaration persists)
    print("\n");
    int total = 0;
    for (int i = 0; i < 3; i = i + 1) {
        int i = 100;        // overwrites the loop variable's slot
        total = total + i;
    }
    printi(total);         // 100 (loop ends after one round: i becomes 101)
    print("\n");
    int a[] = [1, 2, 3, 4];
    int u = 0;
    for (int x : a) {
        int x = 100;
        u = u + x;
    }
    printi(u);             // 400 (4 elements, each read as 100)
    print("\n");
    return 0;
}
output2020 100 400

Because the inner int v = 20 overwrites the outer v, both prints show 20. Likewise, the int i = 100 inside the loop overwrites the loop counter's slot, so the loop body runs once (then i becomes 101, ending the loop) and total is 100. The range-for behaves the same: each of the 4 elements is read as the re-declared 100, giving 400.

Note. A bare { ... } block statement is not valid Flint — the parser expects an expression there. Scope is managed by the language's flat model, not by nested blocks. If you need a distinct value, use a distinct name.

Operators

C-style arithmetic, bitwise, comparison, and logical operators — with a couple of deliberate, documented departures.

Precedence & arithmetic

Standard precedence. Integer division and modulo truncate toward zero (C semantics); the result of % carries the sign of the dividend. && and || short-circuit and yield 0/1. The ternary is right-associative.

examples/ops.flint (selected)
printi(2 + 3 * 4);                    // 14 (precedence)
printi((2 + 3) * 4);                // 20 (parentheses)
printi(-7 / 2);                     // -3 (truncate toward zero)
printi(-7 % 2);                     // -1 (sign of the dividend)
printi(1 << 4);                     // 16
printi(40 >> 2);                    // 10
printi(5 & 3);                     // 1
printi(5 | 3);                     // 7
printi(5 ^ 3);                     // 6
printi(1 || 0);                    // 1 (short-circuit)
printi(0 && 7);                   // 0 (right side not evaluated)
printi(!0);                       // 1
printi(0 ? 10 : (1 ? 30 : 40));  // 30 (right-associative)

Increment evaluates to the new value

This is a deliberate departure from C/Java: x++ and ++x both evaluate to the value after the increment (the post-increment value). There is no "old value" form.

examples/ops.flint (increment section)
int x = 5;
x += 2;                           // x = 7
printi(x++);                       // 8 (x++: value after increment)
printi(++x);                      // 9 (++x: same post-increment value)

Switch & fall-through

switch/case falls through to the next case body when there is no break; break exits the switch. Stacked case labels (with no body between them) share the following body.

examples/monthdays.flint
int daysInMonth(int m) {
    int d = -1;
    switch (m) {
        case 1:
        case 3:
        case 5:
        case 7:
        case 8:
        case 10:
        case 12:
            d = 31;
            break;
        case 4:
        case 6:
        case 9:
        case 11:
            d = 30;
            break;
        case 2:
            d = 28;
            break;
        default:
            d = 0;
    }
    return d;
}

int main() {
    printi(daysInMonth(1));        // 31
    printi(daysInMonth(4));        // 30
    printi(daysInMonth(2));        // 28
    printi(daysInMonth(99));      // 0 (default)
    // explicit fall-through: case 4 matches, prints, falls into case 5
    switch (4) {
        case 4:
            printi(100);
        case 5:
            printi(200);          // reached by fall-through
            break;
        default:
            printi(0);
    }
    return 0;
}
output31 30 28 0 100200

The final 100200 is two prints on one line: case 4 matches, prints 100, then (no break) falls through into case 5's body and prints 200.

Labeled loops

Name a loop with label:, then break label / continue label target it from anywhere inside.

Syntax

Write label: directly before a for or while. Then break label exits that loop from anywhere inside it, and continue label jumps to the next iteration of that (possibly outer) loop.

examples/labels.flint
int main() {
    // break outer: stop the whole nested pair on the first j == 1
    int i = 0;
    int j = 0;
    outer:
    for (i = 0; i < 3; i = i + 1) {
        for (j = 0; j < 3; j = j + 1) {
            if (j == 1) {
                break outer;
            }
        }
    }
    printi(i * 10 + j);            // 1 (stopped at i=0, j=1)
    print("\n");

    // continue outer2: when n == 2, skip the rest of that outer round
    int n = 0;
    int k = 0;
    outer2:
    for (n = 0; n < 4; n = n + 1) {
        for (k = 0; k < 2; k = k + 1) {
            if (n == 2) {
                continue outer2;
            }
            printi(n * 10 + k);
            print("\n");
        }
    }

    // break on a labeled while
    int m = 0;
    lbl:
    while (m < 10) {
        m = m + 1;
        if (m == 3) {
            break lbl;
        }
    }
    printi(m);                   // 3
    print("\n");
    return 0;
}
output1 0 1 10 11 30 31 3

Reading the output: break outer stops the nested pair at i=0, j=1 → 1. The outer2 loop prints 0, 1 (round n=0), 10, 11 (round n=1), skips the n=2 round via continue outer2, then prints 30, 31 (round n=3). Finally the labeled while breaks at m=3.

Functions

Plain function definitions with typed parameters and return values, recursion, pointer arguments, and the @ function-address operator.

Definitions & calls

examples/functions.flint
// Recursion: factorial.
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

// A void function that mutates through a pointer argument.
// Pointer types are written with a leading * : `*int p`.
void increment(*int p) {
    *p = *p + 1;
}

int main() {
    printi(factorial(5)); print(" ");   // 120
    int x = 10;
    increment(&x);              // & = address-of
    printi(x); print(" ");              // 11
    printi(1); print("\n");
    return 0;
}
output (full example: doubleIt(21), factorial(5), increment, @)42 120 11 1

Key points

  • No access modifier needed for free functions — a top-level int name(...) {} is visible across files once the file is part of the compilation (see Modules).
  • Pointers are written with a leading *: *int p, *byte buf. &x is address-of, *p dereferences. See Pointers & raw memory.
  • @ yields a function's address as an int — this is how a function is handed to sys.threadCreate(@fn, arg). See Concurrency.
  • Functions may return early; a void function needs no return.

Exceptions

throw / try / catch / finally — with untyped dispatch and a silent uncaught-throw rule.

Syntax

shape
try {
    // ...
    throw 42;              // raise an int
    // throw new MyError(7);   // or raise an object
} catch (int e) {
    // the first catch receives any thrown value
} catch (MyError e) {
    // ...
} finally {
    // always runs, even on return
}

Semantics (v1)

  • Untyped dispatch. The catch clauses dispatch by position, not by type: the first catch receives any thrown value. The type written in the catch only names the variable's type — v1 performs no runtime type check.
  • finally always runs, including when the try body returns.
  • Uncaught throw = silent return. A throw that reaches the end of its function is swallowed: the function returns and the caller continues normally (the rest of the function body after the throw is not reached).

Worked example

examples/errors.flint
class MyError {
    int code;
    public MyError(int c) {
        this.code = c;
    }
}

int caught_int() {
    try {
        throw 42;
    } catch (int e) {
        return e;
    }
    return -1;
}

int fin_ret() {
    try {
        return 5;
    } catch (int e) {
        return e;
    } finally {
        printi(3);             // runs even though the try returned
    }
}

int uncaught() {
    throw 9;
    printi(12345);           // never reached
}

int main() {
    printi(caught_int() == 42 ? 1 : 0);   // 1
    print("\n");
    try {
        throw new MyError(77);
    } catch (MyError e) {
        printi(e.code);      // 77
    }
    print("\n");
    printi(fin_ret());       // 5 (the 3 above came from finally)
    print("\n");
    uncaught();             // uncaught throw: silent return
    printi(1);               // reached
    print("\n");
    return 0;
}
output1 7 77 35 1

Reading it: 1 (caught 42); 7 (a try that returns normally without throwing); 77 (object throw caught by a class-typed variable); then 3 (from finally) immediately followed by 5 (the return value) — 35 on one line; and 1 (the caller continued after the silent uncaught throw).

Classes & fields

A class with plain fields is a struct. Objects can hold object fields; new fills fields, including nested objects, positionally.

Definition & field access

examples/structs.flint
class Point {
    int x;
    int y;
}

class Rect {
    Point origin;
    int w;
    int h;
}

int main() {
    Point p = new Point(3, 4);
    printi(p.x * 100 + p.y);      // 304
    p.x = 10;
    printi(p.x + p.y);           // 14
    // nested object literal: first field is itself a Point
    Rect r = new Rect(new Point(1, 2), 30, 40);
    printi(r.origin.x);          // 1
    printi(r.origin.y);          // 2
    printi(r.w + r.h);           // 70
    r.w = 50;
    printi(r.w);               // 50
    // an object field can be re-pointed at a different object
    r.origin = new Point(9, 9);
    printi(r.origin.x * 10 + r.origin.y);  // 99
    return 0;
}
output304 14 1 2 70 50 99

Key points

  • Fields are declared as Type name;. Access is obj.field; re-assignment is obj.field = ….
  • Nested objects are written inline: new Rect(new Point(1, 2), 30, 40). The first field origin is itself a Point.
  • Object fields can be re-pointed: r.origin = new Point(9, 9) makes the field refer to a different object.
  • See Constructors for the three ways an object gets its initial values, and Object elements for reference semantics when objects are stored in collections.

Constructors

Three ways an object gets its initial values: a named constructor, positional field fill, or a zero-arg constructor.

The three paths

examples/ctors.flint
class Point {
    int x;
    int y;
    public Point(int a, int b) {
        this.x = a + 1;      // the constructor transforms the args
        this.y = b + 2;
    }
}

class Raw {
    int x;
    int y;
}

class Counter {
    int n;
    public Counter() {
        this.n = 42;
    }
}

int main() {
    Point p = new Point(3, 4);   // (1) routes to the 2-arg constructor
    printi(p.x);                // 4 (3 + 1)
    printi(p.y);                // 6 (4 + 2)
    Raw r = new Raw(10, 20);    // (2) no constructor: positional field init
    printi(r.x * 100 + r.y);   // 1020
    Counter c = new Counter();  // (3) zero-arg constructor
    printi(c.n);               // 42
    Counter c2 = new Counter();
    c2.n = 100;
    printi(c2.n);             // 100 (mutable after construction)
    return 0;
}
output4 6 1020 42 100
  • (1) Named constructor. A method named after the class runs when the new arity matches — it may transform the arguments (this.x = a + 1).
  • (2) Positional fill. With no matching constructor, new Raw(10, 20) fills the fields positionally.
  • (3) Zero-arg constructor. new Counter() runs the no-argument constructor.

Methods, this, super

Methods live inside a class and use this for the current object; super reaches the parent; returning this enables fluent chaining.

this

Inside a method, this is the current object. Fields are read and written through it: this.x.

Fluent chaining

A method that returns this makes calls chainable — p.move(1,1).scale(2).sum() runs left to right on the same object.

examples/fluent.flint
class Point {
    int x;
    int y;
    public Point(int a, int b) {
        this.x = a;
        this.y = b;
    }
    public Point move(int dx, int dy) {
        this.x = this.x + dx;
        this.y = this.y + dy;
        return this;          // enables chaining
    }
    public Point scale(int k) {
        this.x = this.x * k;
        this.y = this.y * k;
        return this;
    }
    public int sum() {
        return this.x + this.y;
    }
}

int main() {
    Point p = new Point(1, 2);
    printi(p.sum());                          // 3
    printi(p.move(1, 1).sum());              // 5 (chained call)
    printi(p.move(2, 2).scale(10).sum());   // (4*10)+(5*10) = 90
    return 0;
}
output3 5 90

super

In a subclass, super(args) calls the parent constructor, and super.method() calls the parent's method. See Inheritance & dispatch for a full example (Dog.bark() uses super.speak()).

Visibility

public / private prefix on fields and methods; the default is public.

Rules

  • Prefix a member with public or private. With no prefix, a member is public by default. There is no protected keyword.
  • private members are visible within the class — including from other instances of the same class (it is class-level, not object-level privacy).

Example

private members, accessed in-class
class Secret {
    private int _val;
    public Secret(int v) { this._val = v; }
    public int getVal() { return _val; }
    public void setVal(int v) { this._val = v; }
    private int hidden() { return 42; }
    public int callHidden() { return this.hidden(); }
    public void copyFrom(Secret other) { this._val = other._val; }
}

int main() {
    Secret s = new Secret(5);
    printi(s.getVal());
    s.setVal(10);
    printi(s.getVal());
    printi(s.callHidden());
    Secret t = new Secret(20);
    s.copyFrom(t);        // reads another instance's private field
    printi(s.getVal());
    return 0;
}
output5 10 42 20

callHidden() returns 42 (a private method called from inside the class), and copyFrom reads other._val — a private field of another instance — because privacy is scoped to the class, not the object.

A static field is a single slot shared by all instances; a static method takes no this and is called through the class name.

Inheritance & dispatch

extends inherits fields and methods; super(args) calls the parent constructor; a re-declared method overrides and dispatches virtually; (Type) x narrows; instanceof tests the type.

Example

examples/animals.flint
class Animal {
    int id;
    public Animal(int a) {
        this.id = a;
    }
    public int speak() {
        return 0;
    }
}

class Dog extends Animal {
    int barks;
    public Dog(int a, int b) {
        super(a);
        this.barks = b;
    }
    public int speak() {            // override
        return 1;
    }
    public int bark() {
        return super.speak() + this.barks;   // parent method via super
    }
}

class Cat extends Animal {
    int meows;
    public Cat(int a, int m) {
        super(a);
        this.meows = m;
    }
    public int speak() {           // override
        return 2;
    }
}

int main() {
    Animal a = new Dog(5, 3);
    printi(a.speak());             // 1 (virtual dispatch through Animal)
    Animal c = new Cat(6, 2);
    printi(c.speak());             // 2
    printi(a.id);                // 5 (inherited field)
    Dog d = (Dog) a;             // narrowing cast
    printi(d.bark());            // 3 (super.speak() + barks = 0 + 3)
    printi(a instanceof Dog);    // 1
    printi(c instanceof Dog);    // 0
    return 0;
}
output1 2 5 3 1 0
  • Virtual dispatch. a.speak() (where a is typed Animal) dispatches to the runtime type's override — 1 for Dog, 2 for Cat.
  • super(args) calls the parent constructor; super.method() calls the parent's method (bark() = super.speak() + barks = 0 + 3).
  • Narrowing cast (Dog) a; instanceof tests the concrete type.

Abstract classes

An abstract class cannot be instantiated; its abstract methods have no body. Concrete subclasses declare them, and calls dispatch virtually through the abstract type.

Example

    abstract int area();
}

class Circle extends Shape {
    int r;
    public Circle(int x) {
        this.r = x;
    }
    public int area() {
        return this.r * this.r;
    }
}

    int s;
    public Square(int x) {
        this.s = x;
    }
    public int area() {
        return this.s * this.s;
    }
}

    return sh.area();              // virtual dispatch
}

    Square q = new Square(4);

Enums

Enum values default to a sequence from 0 (or continue after an explicit value). An enum value is a named int — usable in expressions, stored in a typed variable, and switched on.

Example

Generics

Generic classes and functions are monomorphized at compile time (no runtime type erasure): each (template, type-args) pair expands to a concrete type/function with a mangled name. Nested instantiations expand to a fixpoint.

Example

class Vessel<T> {
    T v;
}

class Pair<A, B> {
    A a;
    B b;
}

T identity<T>(T x) {
    return x;
}

int main() {
    Vessel<int> a = new Vessel<int>(41);
    printi(a.v);                 // 41
    Vessel<string> s = new Vessel<string>("hi");
    print(s.v);               // hi
    int x = identity(7);        // 7 (type inferred from the argument)
    printi(x);
    int y = identity<int>(9);   // 9 (explicit type args)
    printi(y);
    // two type parameters
    Pair<int, string> p = new Pair<int, string>(5, "ok");
    printi(p.a);
    print(" ");
    print(p.b);

Memory model

Object memory is decided at compile time by escape analysis: non-escaping objects live in plain stack slots; escaping objects go to the heap with a refcount header.

Escape analysis

An object escapes when it is passed as an argument, returned, stored in a field, or has its address taken. Escaping objects are heap allocated with a refcount header [refcount][field0][field1]…. Copies retain (flint_retain); drops release (flint_release). Cycles leak in v1 (there are no weak references).

Example

examples/escape.flint
class Pair {
    int a;
    int b;
    public Pair(int x, int y) {
        this.a = x;
        this.b = y;
    }
}

int sum_of(Pair p) {
    return p.a + p.b;
}

Pair make() {
    Pair p = new Pair(9, 8);   // escapes via return -> heap + refcount
    return p;
}

int main() {
    // stack-allocated: never escapes
    Pair s = new Pair(3, 4);
    printi(s.a + s.b);        // 7
    s.a = 10;
    printi(s.a + s.b);        // 14
    // alias of a stack object: plain address, no refcount traffic
    Pair r = s;
    printi(r.b);             // 4
    // heap: escapes into sum_of()
    Pair h = new Pair(5, 6);
    printi(sum_of(h));      // 11
    // heap alias: both hold refcounted references
    Pair c = h;
    c.b = 100;
    printi(h.b);           // 100 (same object)
    // class value returned from a function: fresh reference
    Pair t = make();
    printi(t.a + t.b);      // 17
    // an object stored in a class field is a heap reference
    // ... (see full source for Holder)
    return 0;
}
output (full program)7 14 4 11 100 17 42 7

Key points

  • Stack slot: Pair s = new Pair(3,4) used only locally — no refcount traffic.
  • Heap + refcount: once the object escapes (argument, return, field store, or &), it is heap-allocated and refcounted.
  • Aliases of heap objects both hold refcounted references — writing through one is visible through the other (c.b = 100 → h.b is 100).
  • Returned objects are fresh references.

Pointers & raw memory

Raw pointers (*T, &x, *p) and the heap (alloc/free/ memcpy) are the low-level escape hatch, plus sub-word little-endian access and a generic syscall.

Example

examples/rawmem.flint
int main() {
    // *int pointer to a local: writes go through the address
    int x = 10;
    *int p = &x;
    *p = 99;
    printi(x);                     // 99
    // dynamic array over alloc(); buf[i] is an 8-byte slot
    int n = 5;
    *int fib = alloc(n * 8);
    fib[0] = 0;
    fib[1] = 1;
    int i = 2;
    while (i < n) {
        fib[i] = fib[i - 1] + fib[i - 2];
        i = i + 1;
    }
    int s = 0;
    i = 0;
    while (i < n) {
        s = s + fib[i];
        i = i + 1;
    }
    printi(s);                     // 0+1+1+2+3 = 7
    free(fib);
    // sub-word little-endian access into a buffer
    *byte buf = alloc(16);
    sys.byteStore(buf + 8, 65);
    printi(sys.byteLoad(buf + 8));   // 65 ('A')
    sys.shortStore(buf, 1000);
    printi(sys.shortLoad(buf));      // 1000
    sys.intStore(buf + 12, 0x12345678);
    printi(sys.intLoad(buf + 12));   // 305419896 (== 0x12345678)
    // memcpy: copy 16 bytes
    *byte src = alloc(16);
    src[0] = 111;
    src[1] = 222;
    *byte dst = alloc(16);
    memcpy(dst, src, 16);
    printi(dst[0] * 1000 + dst[1]);   // 111222
    free(src);
    free(dst);
    // generic syscall escape hatch: getpid (39), open (2), close (3)
    int pid = sys.syscall(39, 0, 0, 0, 0, 0);
    printi(pid > 0 ? 1 : 0);        // 1
    int fd = sys.syscall(2, "/dev/null", 0, 0, 0, 0);
    printi(fd >= 0 ? 1 : 0);        // 1
    printi(sys.syscall(3, fd, 0, 0, 0, 0));  // 0 (close ok)
    return 0;
}
output99 7 65 1000 305419896 111222 1 1 0

Key points

  • Pointer type is a leading *: *int p, *byte buf. &x is address-of; *p dereferences; buf[i] reads/writes the 8-byte slot at i.
  • Heap: alloc(n) / free(p) / memcpy(dst, src, n).
  • Sub-word little-endian access: sys.byte/short/intLoad and sys.byte/short/intStore. 0x12345678 loads back as 305419896.
  • Generic syscall: sys.syscall(num, a1..a5) — arguments land in rdi rsi rdx r10 r8 r9 (the 4th is r10). getpid=39, open=2, close=3.

Arrays

Arrays are heap blocks of 8-byte slots with a length header ([len][elem0][elem1]…); they pass by pointer. len(a) reads the header. No bounds checks in v1.

Example

class Grid {
    int data[];
    public Grid(int d[]) {
        this.data = d;
    }
    public int max3() {
        int m = this.data[0];
        int i = 1;
        while (i < 3) {
            if (this.data[i] > m) {
                m = this.data[i];
            }
            i = i + 1;
        }
        return m;
    }
}

    return a[0] + a[1] + a[2];
}

    return [7, 8, 9];
}

    a[1] = 25;

    printi(sum3(a));            // 65 (mutated through the pointer)

    Grid g = new Grid([5, 6, 7]);

  • Literal: int a[] = [10, 20, 30].
  • Pass by pointer: sum3(a) sees a[1] already mutated to 25 (100+25+30 → after a[0]=100, 155).
  • Returning a fresh array: return [7, 8, 9].
  • Array literal as a constructor argument: new Grid([5, 6, 7]).
  • Arrays as class fields (int data[]).
  • len(a) reads the length header; index access is unchecked in v1.

Strings

NUL-terminated byte sequences, passed and stored by pointer. string + int is pointer arithmetic; two strings + concatenate.

The model

  • string + int is pointer arithmetic (an offset), not concatenation. + of two strings concatenates.
  • (string)N is a fresh single-char string for byte value N.
  • A literal stored into a string variable is a fresh writable copy: w[0] = 65 writes an 8-byte little-endian slot, yielding "A" (0x41 00 …). For multi-char builds, use alloc + byte stores + a NUL terminator.

Example

examples/strings2.flint (selected)

    // pointer arithmetic: offset into the byte sequence
    string p = "hello";
    printi(sys.byteLoad(p + 1));  // 101 ('e')
    printi(strlen(p));             // 5

    string s = "hello" + " world";
    print(s);                     // hello world
    printi(strlen(s));            // 11

    string c = (string)72;         // 'H'
    print(c + (string)73);        // HI
    // writable literal copy: the 8-byte slot write yields "A"
    string w = "";
    w[0] = 65;

    sys.byteStore(m + 1, 66);

Fixed-point numbers

Real-valued math is Q48.16 fixed-point — a 64-bit int whose lower 16 bits are the fraction (0.5 == 32768). math.* provides the operations.

The model

There are no floating-point values. A real is a 64-bit int in Q48.16: the low 16 bits are the fraction, so 1.0 == 65536 and 0.5 == 32768. math.itof lifts an int into the format; math.ftoi lowers it (rounding half-up). math.fcmp returns < 0, 0, > 0 like str.cmp.

Example

examples/fixedpoint.flint
int main() {
    int a = math.itof(3);
    int b = math.itof(2);
    printi(math.ftoi(math.fadd(a, b)));        // 5 (3.0 + 2.0)
    printi(math.ftoi(math.fsub(a, b)));        // 1 (3.0 - 2.0)
    printi(math.ftoi(math.fmul(a, b)));        // 6 (3.0 * 2.0)
    printi(math.ftoi(math.fdiv(math.fmul(a, b), b)));  // 3 (6.0 / 2.0)
    printi(math.fcmp(a, b) == 1 ? 1 : 0);      // 1 (3.0 > 2.0)
    printi(math.fcmp(b, a) == -1 ? 1 : 0);    // 1 (2.0 < 3.0)
    printi(math.fcmp(a, a) == 0 ? 1 : 0);     // 1 (equal)
    // fractional: 0.5 + 0.5 = 1.0 (0.5 in Q48.16 is 32768)
    int half = 32768;
    printi(math.ftoi(math.fadd(half, half)));   // 1
    // 1.5 + 2.5 = 4.0  (1.5 = 1*65536 + 32768; 2.5 = 2*65536 + 32768)
    int p15 = 98304;
    int p25 = 163840;
    printi(math.ftoi(math.fadd(p15, p25)));    // 4
    // ftoi rounds half-up: 1.5 -> 2
    printi(math.ftoi(p15));                  // 2 (1.5 rounds up)
    return 0;
}
output5 1 6 3 1 1 1 1 4 2

The final 2 confirms ftoi rounds half-up (1.5 → 2, not truncation to 1). The Math standard-library class builds on these builtins (fround, fceil, ffloor, fsqrt, …).

Collections overview

Five generic collections, each monomorphized per element type: list, queue, hashset, hashmap, and dictionary (an alias of hashmap).

The family

Object elements

Collections holding class objects refcount their elements (the collection layout carries an elem_release slot). Storing an object retains a reference; destroying the collection releases it, but an object referenced elsewhere survives.

Example

examples/obj_coll.flint
class Box {
    int n;
    public Box(int x) {
        this.n = x;
    }
}

int main() {
    // a list of objects
    list b = new list();
    Box a = new Box(1);
    Box b2 = new Box(2);
    b.add(a);
    b.add(b2);
    printi(len(b));                 // 2
    // reading back: the collection's reference keeps the object alive
    Box r1 = b.get(0);
    printi(r1.n);               // 1
    Box r2 = b.get(1);
    printi(r2.n);               // 2
    // the original references still work alongside the collection's
    printi(a.n);               // 1
    printi(b2.n);              // 2
    // a map of objects, keyed by int
    hashmap m = new hashmap();
    m.put(10, new Box(3));
    m.put(20, new Box(4));
    printi(len(m));                 // 2
    Box v = m.get(20);
    printi(v.n);               // 4
    // a queue of objects
    queue q = new queue();
    q.push(new Box(5));
    q.push(new Box(6));
    Box f = q.pop();
    printi(f.n);               // 5 (FIFO)
    Box s = q.pop();
    printi(s.n);               // 6
    return 0;
}
output2 1 2 1 2 2 4 5 6

Semantics

  • Storing retains a reference to the object; reading back yields a reference the collection's own reference keeps alive.
  • The original references (a, b2) work alongside the collection's — they refer to the same objects.
  • Works across list, hashmap (object values), and queue.
v1 limitation. Index writes to object collections (l[i] = obj) use borrow semantics — they store the pointer without retaining, and do not release the displaced element. Prefer add/put for object elements; a program that mixes add with index-overwrites of the same slot can leak or double-free the displaced object. threadJoin is a separate known limitation — see Concurrency.

Example — one worker per CPU (verified)

Count the primes in [2, N] by splitting the range into K = nCpu() chunks, one per thread, all spawned up front (so they run concurrently, in tandem) and joined one by one:

examples/primes_thread.flint
import std.Thread;

class Cfg {
    static int N;  // upper bound (inclusive)
    static int K;  // number of workers (= nCpu())
}

int isPrime(int n) {
    if (n < 2) { return 0; }
    if (n == 2 || n == 3) { return 1; }
    if (n % 2 == 0 || n % 3 == 0) { return 0; }
    int i = 5;
    while (i * i <= n) {
        if (n % i == 0 || n % (i + 2) == 0) { return 0; }
        i = i + 6;
    }
    return 1;
}

int worker(int k) {
    int span = (Cfg.N - 2 + 1) / Cfg.K;
    int lo = 2 + k * span;
    int hi = lo + span - 1;
    if (k == Cfg.K - 1) { hi = Cfg.N; }   // last chunk takes the remainder
    int count = 0;
    int n = lo;
    while (n <= hi) {
        if (isPrime(n) == 1) { count = count + 1; }
        n = n + 1;
    }
    return count;
}

int main() {
    int N = 1000;
    Cfg.N = N;
    int K = Thread.nCpu();            // one worker per CPU
    Cfg.K = K;
    for (int k = 0; k < K; k = k + 1) {
        Thread.spawn(@worker, k);      // spawn all up front (run in tandem)
    }
    int total = 0;
    for (int k = 0; k < K; k = k + 1) {
        total = total + Thread.join(k); // join each, sum the per-chunk counts
    }
    printi(total == 168 ? 1 : 0);      // 1 (168 primes below 1000)
    return 0;
}

Standard library: Image

import std.Image; — pixel buffers, transforms, drawing, and multi-format I/O. Pixels are a row-major RGBA byte buffer (4 bytes/pixel); packed colors are 0xAARRGGBB in a 64-bit int. Not covered by the README — this is the one stdlib class you won't find there.

Color & pixel R/W

Static: rgba(r,g,b,a) rgb(r,g,b) cr cg cb ca (channel getters). Instance: get(x,y) (packed, 0 out of range) set(x,y,c) setAlpha r g b a (individual channels).

Transforms & drawing

Whole-image: fill clear invert grayscale flipH flipV. Instance: scale(nw,nh) (nearest-neighbor, returns a new image) blur (3×3 box). Drawing: hline vline fillRect rect line circle fillCircle.

I/O (by extension)

save(path) dispatches on the extension: .png → toPng, .bmp → toBmp, .pgm → toPgm, else toPpm. Image.load(path) detects by magic bytes (PNG / "BM" / "P5" / PPM). Also fromPpm / fromPgm / fromBmp / fromPng. save/to_* return the byte count written.

Example

examples/image_demo.flint
import std.Image;

int main() {
    // A 64x64 RGBA image (4 bytes/pixel, row-major)
    Image im = new Image(64, 64);
    im.fill(Image.rgb(255, 0, 0));              // solid red
    im.fillCircle(32, 32, 20, Image.rgb(0, 255, 0)); // green filled disc
    // The centre is inside the disc -> green; a corner is red
    int centre = im.get(32, 32);
    int corner = im.get(0, 0);
    printi(Image.cg(centre) > 200 ? 1 : 0); // 1 (green centre)
    printi(Image.cr(corner) > 200 ? 1 : 0); // 1 (red corner)
    // Grayscale then rotate 90 (64x64 stays 64x64)
    im.grayscale();
    im.rotate90();
    int p = im.get(10, 10);
    printi(Image.cr(p) == Image.cb(p) ? 1 : 0); // 1 (channels equal)
    // Save as BMP (returns the byte count), load it back, round-trip check
    int r = im.save("/tmp/flint_image_demo.bmp");
    printi(r > 0 ? 1 : 0);                    // 1 (saved ok)
    Image back = Image.load("/tmp/flint_image_demo.bmp");
    printi(back != null ? 1 : 0);             // 1 (loaded)
    printi(Image.cr(back.get(10, 10)) == Image.cr(p) ? 1 : 0); // 1
    // scale() returns a new image (nearest-neighbor)
    Image big = im.scale(32, 32);
    printi(big != null ? 1 : 0);             // 1
    return 0;
}

Standard library: Thread

import std.Thread; — spawn/join worker threads (one per CPU) and read the CPU count, hiding the raw sys.threadCreate/threadJoin and the sched_getaffinity syscall.

Methods

nCpu spawn join

Example

examples/primes_thread.flint
import std.Thread;

class Cfg {
    static int N;  // upper bound (inclusive)
    static int K;  // number of workers (= nCpu())
}

int isPrime(int n) {
    if (n < 2) { return 0; }
    if (n == 2 || n == 3) { return 1; }
    if (n % 2 == 0 || n % 3 == 0) { return 0; }
    int i = 5;
    while (i * i <= n) {
        if (n % i == 0 || n % (i + 2) == 0) { return 0; }
        i = i + 6;
    }
    return 1;
}

int worker(int k) {
    int span = (Cfg.N - 2 + 1) / Cfg.K;
    int lo = 2 + k * span;
    int hi = lo + span - 1;
    if (k == Cfg.K - 1) { hi = Cfg.N; }   // last chunk takes the remainder
    int count = 0;
    int n = lo;
    while (n <= hi) {
        if (isPrime(n) == 1) { count = count + 1; }
        n = n + 1;
    }
    return count;
}

int main() {
    int N = 1000;
    Cfg.N = N;
    int K = Thread.nCpu();            // one worker per CPU
    Cfg.K = K;
    for (int k = 0; k < K; k = k + 1) {
        Thread.spawn(@worker, k);      // spawn all up front (run in tandem)
    }
    int total = 0;
    for (int k = 0; k < K; k = k + 1) {
        total = total + Thread.join(k); // join each, sum the per-chunk counts
    }
    printi(total == 168 ? 1 : 0);      // 1 (168 primes below 1000)
    return 0;
}
